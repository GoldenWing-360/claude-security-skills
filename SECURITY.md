# Security Policy

## Scope

This repository contains **documentation and Markdown skills** — there is no executable code that runs in production. Most security issues will be in one of three forms:

1. **A skill recommends an unsafe or outdated pattern** (the most likely class)
2. **A skill contains an accidentally-real credential, IP, or IOC**
3. **An issue with the repo's own configuration** (CI, workflows if/when added, branch protection, etc.)

## How to report

**Do not open a public issue for security-relevant problems.** Instead:

- Email: `office@goldenwing.at`
- Or use GitHub's [private vulnerability reporting](https://github.com/GoldenWing-360/claude-security-skills/security/advisories/new) for this repo

Include:

- Which skill or file the issue affects (path + line number if possible)
- What is wrong and why it matters
- A suggested fix if you have one

We will acknowledge within 72 hours and aim to resolve within 14 days for advice-correctness issues. Accidental-credential leaks are treated as immediate.

## What counts as a security issue here

Yes:

- A recommended command, flag, or library that has a known CVE or known-bad behavior
- A code snippet that, if followed, would introduce a vulnerability
- An IP, credential, or customer-identifying data that slipped through review
- A typosquat-shaped package name in an example (could lead readers to malicious packages)

Not necessarily security issues (open a normal issue):

- Stylistic disagreements
- Skill scope gaps (open a feature request / new-skill proposal)
- "I would have written it differently" — open a PR

## Out of scope

- Reports auto-generated by scanners with no human review — please confirm the finding is real before reporting
- Issues with third-party tools the skills reference (report those upstream)
- The general topic of "AI / LLM-generated content might be wrong" — yes, that is why the skills are reviewed by humans
